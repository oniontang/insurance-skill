## 2. 信息不足版

```markdown
## 暂不做完整复盘

现在缺少原始沟通材料，只能做框架判断。

请补充：
1. 客户原话或聊天记录。
2. 这次沟通的目标。
3. 你已经发过哪些材料。
4. 客户最后停在哪一句。
5. 你希望下一步约电话、补资料，还是处理异议？

没有原始材料时，不能判断客户真实阶段，也不能补不存在的成交意向。
```

## 3. 质量标准

| 维度 | 满分 | 合格标准 |
|---|---:|---|
| 事实准确 | 25 | 明确区分事实和推断 |
| 阶段判断 | 20 | 能判断客户处在哪一步 |
| 卡点清楚 | 20 | 只抓主要卡点，不泛泛而谈 |
| 动作明确 | 20 | 下一步有人、事、材料和时间 |
| 边界控制 | 15 | 不承诺成交、理赔、核保、医疗、法律或收入结果 |

## 4. 必须收住

- 没有原始材料，不做高置信度判断。
- 不补不存在的成交意向。
- 不把客户沉默自动解读成拒绝。
- 不把复盘写成流水账。
- 不用“多沟通、多跟进”这种空动作。

## 评分补强：输入校验、错误码和恢复

### 输入校验

| 字段 | 处理 |
|---|---|
| 聊天记录 | 缺失时标为待确认，必要时先追问 |
| 面谈记录 | 缺失时标为待确认，必要时先追问 |
| 方案讲解记录 | 缺失时标为待确认，必要时先追问 |
| 跟进结果 | 缺失时标为待确认，必要时先追问 |
| 顾问复盘备注 | 缺失时标为待确认，必要时先追问 |

缺少关键字段时，先输出“信息不足版”，不要把初判写成终稿。

### 错误码

| 代码 | 触发 | 输出 |
|---|---|---|
| `E001_INPUT_MISSING` | 缺关键字段 | 缺口清单 + 最小追问 |
| `E002_CONTEXT_WEAK` | 只有抽象目标 | 低置信初判 + 待补材料 |
| `E003_SCOPE_OUT` | 不属于本 Skill | 交接建议 |
| `E004_FACT_CONFLICT` | 材料冲突 | 冲突项清单 |
| `E005_REVIEW_REQUIRED` | 需要外部专业判断 | 待确认表达 + 核对提醒 |

### 默认值

- 未提供目标对象：默认写“目标对象未提供”，不自行补人群。
- 未提供材料来源：默认写“来源待确认”，不当作事实。
- 未提供输出对象：默认先给顾问内部版，不直接写客户版。
- 未提供时间范围：默认不写具体周期，只写下一步动作。

### 重试与恢复

- 输出缺少 `沟通摘要、事实推断分离、客户阶段判断、销售卡点、沟通表达诊断、下一步动作` 中的关键模块时，按默认模板重写一次。
- 输出出现确定承诺时，删除该句，改成条件判断和待确认项。
- 用户只要快速版时，仍保留输入校验、核心判断、下一步动作和边界提醒。

## 评分补强二：触发、输出校验与重试

### 触发判断

先判断任务是否属于本 Skill。适合则继续，不适合则说明原因并交接。

### 输出结构校验

每次输出必须包含：输入校验、一句话判断、沟通摘要、事实推断分离、客户阶段判断、销售卡点、沟通表达诊断、下一步动作、依据与缺口、下一步动作、边界提醒。

### 重试规则

- 第一次输出缺模块：按 `references/output-schema.md` 补齐。
- 第二次仍缺模块：重写完整答案。
- 重写 2 次仍不合格：标为 `needs_review`，不要继续生成。

### 平台运行约定

- 输入预检：`scripts/quality_gate.py`
- 输出校验：`scripts/output_validator.py`
- 重试判断：`scripts/retry_policy.py`
