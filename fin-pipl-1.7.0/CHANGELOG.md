## v1.7.0

本次不新增检查项，**只修交付面**：免责声明，以及一处被版本迭代带过时的文档样例。

### 为什么动免责声明

对 skill 做自我检查时发现：免责表述实际散在 **4 处**（`DISCLAIMER.md` 44 行 / `SKILL.md` 节 38 行 / `README.md` 一句 / **报告产物页脚**），其中 **8 条义务只出现在一处**——两份文件不是"子集关系"，而是同一模板分头演化后各自停在了不同的位置。例如：

- 「**使用本工具即表示同意以上条款**」只在 `DISCLAIMER.md`，而它**不在打包白名单**里。按白名单打包，这句根本发不出去，44 行免责退化成读者看不到的附件；按目录整体上传，又会和 `SKILL.md` 那 38 行同时出现且互相打架；
- 「本工具**覆盖的法规范围以声明为准**」没有任何"声明"被命名或指向（`SKILL.md`／`README.md` 都不提 `DISCLAIMER.md`），是空指代；
- 而**最该有的那条，四份文件都没有**：没有一处说明「结论完全取决于用户自述、工具未作核实」。`SKILL.md` 正文写了「本工具是自述式问卷，不是核实」，法律声明里却一个字没有；生成的报告里「自述」出现 **0 次**——而报告正是唯一会被交出去留档的那份。

## v1.6.0

本次补的是 **PIPL 里一条被整个工具漏掉的核心义务**：个人信息保护影响评估。

### 为什么是缺口

PIPL 第五十五条列举了五种情形，应当在**事前**进行个人信息保护影响评估并对处理情况作记录：

1. 处理敏感个人信息；
2. 利用个人信息进行自动化决策；
3. 委托处理个人信息、向其他个人信息处理者提供个人信息、公开个人信息；
4. 向境外提供个人信息；
5. 其他对个人权益有重大影响的个人信息处理活动。

第五十六条规定了评估内容，并要求**评估报告和处理情况记录至少保存三年**。

问题在于：本工具**一直在问这些"触发行为"本身**（敏感信息单独同意、自动化决策的告知与解释、第三方共享的单独同意、跨境出境路径），**却从未问过"你有没有据此做过影响评估"**。
触发条件都查了，义务本身漏了——这是明显的覆盖缺口。

### 新增（检查项 30 → 34，问答项 115 → 123）

四个场景各新增 1 项「个人信息保护影响评估 - 事前评估与记录留存」（共用同一组问答）：

| 问题 | 作用 |
|---|---|
| 是否涉及任一触发情形（敏感个人信息／自动化决策／委托处理或对外提供或公开／跨境／其他重大影响）？ | **前置**：答 `n` ⇒ 本项判「不适用」（沿用 v1.3.0 的统一判据） |
| （若涉及）是否已在事前完成影响评估，并按不短于三年的期限留存评估报告与处理情况记录？ | 答 `n` ⇒ **未通过**（PIPL 用的是「应当」，属强制义务） |

各场景项数：银行 9→10｜证券 7→8｜保险 7→8｜支付 7→8。

### ⚠️ 一条必须说清的限制：这是自述式

「留存不短于三年」这个动作，**问卷里没法检查，只能问**——而且比一般自述更绕一层：

影响评估是**事前**做的，**在评估当口三年还没过完**。所以**任何工具**（不只是本工具）都不可能在那一刻核实"是否已留存三年"。
能问的只有**机制**：是否**已设立**不短于三年的保存期限、并照此留存。

本工具是纯本地离线运行，拿不到机构的文档系统或留存台账，因此**只能是自我检查问卷**。
这一点已写进 SKILL.md 的「关于『能不能真的检查到』」一节与检查项说明，**不装成"已核实"**。

### 引用

本项依据按本工具既定口径写到条号：`PIPL Art.55, 56`（PIPL 属允许写到条号的层级，条号与内容已核对中国人大网公布的法律全文原文）。

### 校验

- 新增 Art.55 定向实测：前置 `n` ⇒ N/A｜`pipia_done=n` ⇒ FAIL 且说明含"影响评估"｜全 `y` ⇒ PASS｜依据为 `PIPL Art.55, 56`。
- 不变式穷举 4 场景 × 808 组 ⇒ **0 处矛盾**；全 `y` 时四场景均无 N/A、合规率 100%。
- 文档↔代码对账：34 项逐项对应，问答项合计 123。
- 既有 `--demo`、台账、四场景回归、`网络营销` 定向实测全部重跑通过。

### 新增（检查项 25 → 30，问答项 95 → 115）

## v1.3.0

本次做的是「消除自相矛盾」——把几处口径不一致的地方收敛成**可机械检验的不变式**。

### 修复（自相矛盾）

- 🔴 **「✅ 通过」却挂着一句缺陷描述**
  25 个检查方法都列举了问题清单，但 `passed` 只看了其中**一部分**。
  结果一个标着 ✅ 的项下面会写「未提供自动化决策结果的解释说明机制」「健康数据留存期限未明确限定」等，
  到底是通过还是没通过，读不出来。
  **现在统一为一条不变式：`passed` 恒等于「没有任何问题」。** 25 个方法逐一改过。

- 🔴 **同一件事两种相反结论**
  同样是「本机构不涉及这项」，原先有的判 **PASS**（未涉及再保险、未涉及跨境传输、未使用自动化决策、
  未收集受益人信息、未收集商户经营者信息），有的判 **WARN**（未使用支付标记化）。
  更糟的是那 5 个 PASS **计入合规率分母**——等于「没检查」被算成「合规」，**合规率被虚高**。
  **现在统一为「不适用」，且不计入分母。**

### 新增（「不适用」状态）

判据只有一条，全项目统一：

> **该检查项针对的业务活动或技术机制，在本机构不存在 ⇒ 判「不适用」。**

- 与「业务存在但措施未落实」严格区分——后者仍是 WARN / FAIL（应做未做）。
- 合规率分母改为**适用项数**：`合规率 = 通过数 ÷ 适用项数`。
- 控制台、Markdown、HTML、JSON、台账**五处口径一致**，报告单列「不适用」项与数量。
- 台账对比新增「🔁 适用性变化」一类（适用性变化既不算改善也不算退步）。
- 触发方式：每个可能不适用的检查项都有前置的「是否涉及」问题，答 `n` 即判不适用。

### 变更（法规引用口径）

- 📚 引用**只写到能核对的层级**：
  - **PIPL 写到条文号**（如 `PIPL Art.24`）——条号与内容已逐条核对中国人大网公布的**法律全文原文**；
  - **行业标准与其余法规只写名称、去掉章条号**。原先存在的 `JR/T 0171 5.1/5.2/5.3/6.2/4.2`、
    `JR/T 0197 5.2`、《征信业管理条例》`Art.18/19/25`、《保险法》`Art.16`、
    《金融消费者权益保护实施办法》`Art.16/21`、《证券期货投资者适当性管理办法》`Art.6`
    等章条号，**无法从本包内核实，已全部去掉**。
- ➕ 银行场景新增 1 个问答项（第三方营销共享是否取得单独同意），使原先「只提示不判定」的一项成为可判定项。
  全场景问答项 94 → **95**。

### 校验

新增一致性校验（穷举 4 场景 × 808 组作答组合）：

| 不变式 | 内容 |
|---|---|
| I1 | 未通过的项必须有说明，不得空描述 |
| I2 | `severity == "PASS"` ⇒ `passed` 为真且适用 |
| I3 | `severity == "N/A"` ⇒ 不适用、不带建议、不算通过 |
| I4 | 合规率分母 == 适用项数；`passed` 的项必须适用 |
| I5 | 检查方法消费的字段 ↔ 场景问答列表 双向对齐 |
| I6 | SKILL.md 检查项概览的项数与代码实有一致 |
| I7 | 引用中不出现无法核对的章条号 |

结果：**0 处矛盾**。全 `y` 作答时四场景均为 `不适用=0、合规率 100%`。

## v1.2.0

### 新增（粘性 · 从「一次性检查」到「持续合规管理」）

- 📗 **合规台账 `--ledger FILE`**：把每次检查结果追加进一个 JSONL 台账，
  并在同一次运行里读取**该场景上一次记录**做逐项对比，输出：

  ```
  📈 与上次相比（上次：2026-09-26 12:40:16，合规率 75% → 75%，+0 个百分点）
  ```

- 台账**跨场景共用一个文件**，按场景各取各的上次记录，互不干扰。
- 对比结果进入**控制台、Markdown、HTML、JSON** 四种输出。

### 变更

- 🔧 控制台输出为**未通过项**补打一行 `依据:`（标记为 PASS 的项不打印，保持输出聚焦于要整改的地方）。
  Markdown / HTML 报告此前已含 `法规依据` 字段，本次只是让控制台与之一致。

### 边界（均有实测）

- ➕ 交互式问答显示进度 `[i/total]`
- ➕ 答案文件缺项时，逐条列出缺失的问题 id 后再退出（退出码 2）
- ➕ 场景不匹配、非法 JSON、文件不存在等均有明确错误提示
- ➕ `--interactive` 与 `--input` 互斥校验；`--save-answers` 仅配合 `--interactive` 生效
