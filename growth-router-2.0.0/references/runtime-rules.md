# 运行规则

## 上下文读取

每次先读取当前对话，按下面 5 类提取：

- 用户原话。
- 已确认事实。
- 已有材料或文件。
- 已完成步骤与上一轮结果。
- 用户当前想推进的动作。

用户没有提供的内容标为待确认，不自行补写。

## 最小追问

信息不完整不等于不能开始。只有两个候选 Skill 无法区分，而且答案会改变当前主 Skill 时，才问 1 个问题。

不要使用通用问卷，不要一次问 5 个字段。

## 模式状态

| 状态 | 处理 |
|---|---|
| `onboarding_ready` | 输出首次使用说明 |
| `direct_skill` | 交给用户点名的 Skill |
| `ready` | 输出单主 Skill 路由并交接 |
| `no_match` | 说明当前线上暂无对应 Skill，不输出本地未发布名称 |
| `needs_more_info` | 问 1 个决定性问题 |
| `needs_review` | 停止确定性输出，说明风险或冲突 |

## 错误与恢复

| 错误 | 恢复动作 |
|---|---|
| 选择了多个主 Skill | 保留当前最能推进任务的 1 个，其余不展示 |
| 路由到目录外名称 | 回到 `skill-catalog.md` 重新选择 |
| 重复追问已有信息 | 删除问题，直接复用对话内容 |
| 把固定六环节当执行链 | 回到用户眼前材料，重新判断当前动作 |
| 声称已调用但没有结果 | 改为交接卡，不虚构平台能力 |
| 出现确定性专业承诺 | 删除承诺，标明事实来源和待确认项 |
| 材料前后冲突 | 停止终稿，列出会改变路由的冲突点 |

## 重试

第 1 次失败时，只修正多主 Skill、无效名称或缺失交接字段。第 2 次仍失败时，重写完整路由。两次后仍不合格，返回 `needs_review`。

## 脚本

- `scripts/quality_gate.py`：识别模式、点名 Skill 和风险表达。
- `scripts/output_validator.py`：检查单主 Skill、目录有效性、必填结构和交接方式。
- `scripts/retry_policy.py`：控制最多 2 次重写。

平台不能运行脚本时，按同样规则人工自检。
