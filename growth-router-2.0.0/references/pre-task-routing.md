# 任务前路由

## 判断顺序

1. 读取当前对话，提取用户原话、材料、目标、限制和已经做过的步骤。
2. 检查用户是否明确点名具体 Skill；点名时直接尊重，不重新分流。
3. 判断用户眼前要完成的动作，不要求他从六环节重新开始。
4. 只在 `skill-catalog.md` 的 23 个线上子 Skill 中选择 1 个主 Skill。
5. 只有两个方向无法区分，而且答案会改变主 Skill 时，问 1 个关键问题。
6. 按 `handoff-contract.md` 交接。

## 直接材料优先

用户已经拿出具体材料时，优先按材料和动作路由：

| 用户手里的东西或动作 | 主 Skill |
|---|---|
| 面谈录音、转写、笔记，要整理事实和跟进 | 会议纪要 |
| 客户聊天，对方说贵、再想想、家人不同意 | 异议处理 |
| 一份计划书或保险方案，要讲给客户听 | 方案呈现 |
| 养老金基础数据，要快速估算 | 养老金测算 |
| 一段朋友圈草稿或发圈目的 | 朋友圈 |
| 一段短视频选题、素材或逐字稿 | 短视频 |
| 一篇长内容或课程稿，要转成长视频 | 长视频 |
| 小红书选题、正文或 9 张图 | 小红书 |
| 公众号选题、大纲或正文 | 公众号长文 |
| 续保、缴费或保全材料 | 续保维护 |
| 一段客户沟通，要判断为什么没推进 | 销售复盘 |

不要因为用户没有定位材料，就阻止这些具体任务开始。

## 按意图路由

### 定位与人设

| 信号 | 主 Skill |
|---|---|
| 不知道服务谁、解决什么，或 PSP 是否成立 | PSP定位诊断 |
| 已有定位，想判断八大人群中的目标客群 | 八大人群 |
| 已有定位，要转成场景、话题、语调、情绪、妆造 | 定位元素表 |
| 账号身份不清、信任感弱、表达不像本人 | 账号人设 |

### 内容

| 信号 | 主 Skill |
|---|---|
| 不知道长期讲什么、各渠道怎么分工 | 内容策略 |
| 明确要写一条朋友圈 | 朋友圈 |
| 明确要做短视频 | 短视频 |
| 明确要做 8～20 分钟长视频 | 长视频 |

### 咨询与销售

| 信号 | 主 Skill |
|---|---|
| 客户刚主动来问，需要破冰、筛选和约电话 | 预咨询 |

| 不确定客户是否值得继续推进 | 客户筛选 |

| 要讲解计划书或帮助客户比较方案 | 方案呈现 |
| 要整理面谈记录和后续动作 | 会议纪要 |

| 信号 | 主 Skill |
|---|---|

## 常见冲突

| 两个候选 | 用什么区分 |
|---|---|
| 内容策略／具体内容 Skill | 要决定长期讲什么用内容策略；要产出一条内容用具体内容 Skill |
| 预咨询／轻咨询 | 客户刚来、目标是筛选和约电话用预咨询；已约到时间、目标是完成一场咨询用轻咨询 |
| 客户筛选／异议处理 | 不确定客户是否值得推进用客户筛选；已出现明确反对理由用异议处理 |
| 会议纪要／销售复盘 | 要整理发生了什么用会议纪要；要判断为什么没推进用销售复盘 |
| 朋友圈／账号人设 | 要写今天这条内容用朋友圈；要解决长期身份和信任呈现用账号人设 |
| 养老金测算／方案呈现 | 要算基础缺口用养老金测算；已有方案、要讲给客户听用方案呈现 |

无法区分时只问决定性问题，例如：“你现在要先还原这次面谈发生了什么，还是判断它为什么没有推进？”

## 线上暂无对应 Skill

用户提出理赔、教育金测算、直播、转介绍、服务复盘、短视频复盘、API 桥接等需求时，先确认 `skill-catalog.md`。当前目录没有对应 Skill 就直接说明，不输出本地未发布名称，也不把不匹配的线上 Skill 硬凑成答案。
