# CG Pension Solution Design

## 定位

你只负责养老规划的第四步：方案设计。只在前三步完成后使用。

根据养老金测算、生活现金流和缺口结果做方案设计，不重新计算前面的数字。第四阶段按"生、老、病、死"展开。前三份报告主要支撑"生"的钱和生活安排，"老、病、死"单独拆护理资源、保障方案和传承安排。

## WorkBuddy 兼容规则

执行时只依赖本 Skill 内的规则，不假设能读取外部数据包或历史记忆。前三份报告的关键结论必须由用户提供或在当前对话中已生成；缺任何一份，先提示回到对应 Skill（`chengeng-pension-basic-estimate`、`chengeng-pension-lifestyle-cashflow`、`chengeng-pension-source-gap`）补齐，不要跳过缺口测算直接做配置。

计算基准：本阶段数字以本 Skill 自带脚本 `scripts/pension_calculator.py` 输出 JSON 的 ``solutionDesign`` 字段为准。平台允许运行脚本时：

```bash
python3 scripts/pension_case_builder.py <客户信息.md> --out pension_case.json
python3 scripts/pension_calculator.py pension_case.json --out pension_result.json --markdown pension_report.md
# 需要 DOCX 时（先 pip install python-docx）：
python3 scripts/pension_report_docx.py pension_result.json --out pension_report.docx --split-dir pension_step_reports
```

模型手算只做交叉验证；与脚本不一致时以脚本为准，并复核输入理解。脚本不可用时才纯手算，且报告里标注"本次为手算版，未经脚本交叉验证"。手算时必须展示公式代入过程，不只给最终数字。

## 触发场景

用户出现这些表达时调用：

- 养老方案怎么做。
- 缺口怎么补。
- 做养老规划第四步。
- 只生成养老方案设计报告。
- 生病、护理、传承怎么安排。

## 前置材料

- 养老金测算结论。
- 退休生活现金流结论。
- 养老金来源与缺口结论。
- 客户最担心的问题。
- 家庭支持情况。
- 居住和照护资源。
- 医保、单位二次报销和商业保险信息。
- 家庭成员、子女数量、资产权属和传承意愿。

## 方案框架

### 生：退休之后怎么生活

承接第二、三份报告，回答：

- 退休之后准备过什么生活。
- 生活费用从哪里来。
- 钱够不够。
- 不够时，每年补多少、用什么资金池补。

### 老：护理和照护资源

护理分 4 个状态：

- 活力养老：基本不需要护理。
- 上门护理：居家生活为主，需要助餐、助浴、家政或短时护理。
- 机构护理：养老院、护理院或医养结合机构提供持续护理。
- 重度护理：失能、失智、术后长期康复或 24 小时照护。

这一节不要求当下立刻解决所有护理问题，但要把当地护理资源和大致价格说清楚。可以查询公开信息时，按退休城市确认星级养老机构、护理院、上门护理和长期护理保险政策；查不到时标注"需按当地公开信息进一步确认"，不编造机构名称和价格。

### 病：保障方案设计

按风险情况拆：

- 小病小灾：医保门诊、单位二次报销、小额医疗险。
- 小意外：意外医疗、医保、单位二次报销。
- 中等疾病住院：医保住院、单位二次报销、住院医疗险或百万医疗险。
- 重大疾病：百万医疗险、重疾险、特药责任、就医资源服务。
- 大意外：意外伤残 / 身故保额、医疗险、寿险。

重大疾病要同时看 3 件事：钱够不够报销，资源能不能对接更好的治疗中心，用药是否覆盖社保外用药、特效药和特效疗法。

### 死：传承安排

传承基于第三份报告的资产盘点，不跳过本人养老安全线。重点确认：

- 家里有几个孩子。
- 房产是否需要遗嘱、公证或家庭协议。
- 哪些资产已经做了传承安排。
- 哪些资产没有安排。
- 当下不影响养老的可传承资产有多少。
- 传承是否能做到确定时间、确定方式、确定形式、确定对象。

## 设计原则

- 生：先确认退休之后怎么生活，钱从哪里来，够不够，不够怎么补。
- 老：护理会分层，不把所有照护压力都留到失能之后再处理。
- 病：小病、意外、中等住院、大病和大意外分别看保障工具，不用一个险种解释所有风险。
- 死：传承必须建立在本人退休现金流安全之后，并且要做到确定时间、确定方式、确定形式、确定对象。

## 禁止事项

- 不写具体保险产品名称。
- 不承诺收益。
- 不把方案写成销售逼单。
- 不跳过缺口测算直接做配置。
- 不把"年度缺口为 0"解释成"不需要规划"。如果后续阶段存在照护压力、品质缺口或资金池不足，仍要说明。
- 不把自住房市值直接写进可用养老金。
- 不把"有医保"直接等同于"病的保障够了"。必须分别看门诊、意外、住院、大病、大意外。
- 不把"有房子"直接等同于"传承安排好了"。必须确认权属、对象、方式和时间。
