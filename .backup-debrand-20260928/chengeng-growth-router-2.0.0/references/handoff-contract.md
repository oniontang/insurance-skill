# Skill 交接契约

## 先判断运行环境

路由结论出来后，检查当前平台是否真的支持调用另一个已安装 Skill。不要根据想象判断。

### 通道 A：支持 Skill 间调用

1. 说明本次选择的主 Skill 和依据。
2. 把当前对话中的任务、材料、事实、缺口和输出目标交给目标 Skill。
3. 立即执行目标 Skill，不要求用户重新粘贴材料。
4. 目标 Skill 返回结果后，再由总入口根据新结果导航。

对用户只说一句：

> 这一步交给「陈庚-{功能}」，因为 {一句依据}。我直接沿用你刚才的材料继续。

只有收到目标 Skill 的实际结果，才能说“已经调用”或“已经完成”。

### 通道 B：不支持 Skill 间调用

输出目标 Skill 和交接卡。交接卡应能让用户直接继续，不需要重新整理材料。

```markdown
## 当前判断

- 主 Skill：陈庚-{功能}
- 现在先处理：{当前任务}
- 判断依据：{1-3 条}

## 交接卡

- 用户原话：{保留关键原话}
- 当前任务：{一个明确动作}
- 已确认事实：{只写材料中已有的事实}
- 已有材料：{文件、聊天、数据或上一轮结果}
- 待确认项：{只列会影响执行的缺口}
- 希望产出：{目标 Skill 应交付什么}
- 专业边界：{本次需要特别注意的边界}

## 下一步

打开「陈庚-{功能}」，把这张交接卡发给它即可。
```

## 交接质量

- 不把推断写进“已确认事实”。
- 不丢失用户原话和已上传材料。
- 不要求用户再次回答当前对话里已经回答的问题。
- 不附带一串备用 Skill。
- 不把内部推理过程交给客户。
- 涉及产品、条款、理赔、核保、医疗、法律和收益时，标明需要核对的来源和责任边界。
