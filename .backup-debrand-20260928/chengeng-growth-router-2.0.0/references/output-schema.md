# 输出结构与校验

## 首次使用

必须讲清：

- 用户可以提交真实问题、材料、目标或卡点。
- 用户不需要先判断 Skill，也不需要把材料整理完整。
- 现在直接提交最近要推进的事情。

首次使用不展示完整目录，不套用路由报告模板。

## 任务前路由与任务后导航

最小输出：

```markdown
## 当前判断

- 主 Skill：陈庚-{功能}
- 现在先处理：{当前任务}
- 判断依据：{用户原话或材料证据}

## 还缺什么

- {关键缺口；没有则写“可以直接开始”}

## 下一步

{直接调用，或交接卡。}
```

校验要求：

- `主 Skill` 只能有 1 个。
- 主 Skill 必须存在于 `skill-catalog.md`。
- 用户明确点名 Skill 时，不输出另一个主 Skill。
- 不把后续可能性写成第二个主 Skill。
- 不支持跨 Skill 调用时，交接卡包含用户原话、当前任务、已确认事实、已有材料、待确认项、希望产出和专业边界。

线上没有对应能力时不写主 Skill，改用：

```markdown
## 当前判断

- 线上匹配：暂无对应 Skill
- 当前需求：{用户要完成的事}
- 原因：{线上目录缺少哪类能力}

## 下一步

{说明替代动作。}
```

## 体系说明

只需说明应交给 `陈庚-增长体系`，并沿用当前问题。不要在总入口里展开六环节课程。

## 状态

| 状态 | 条件 | 处理 |
|---|---|---|
| `onboarding_ready` | 进入首次使用 | 输出新手说明并等待真实任务 |
| `direct_skill` | 用户明确点名单体 Skill | 尊重用户选择，不改道 |
| `ready` | 已选出 1 个有效主 Skill | 直接调用或输出交接卡 |
| `no_match` | 23 个线上子 Skill 均不匹配 | 明确说明当前线上暂无对应能力 |
| `needs_more_info` | 两个候选无法区分 | 只问 1 个决定性问题 |
| `retry` | 多主 Skill、名称无效或缺交接 | 按最小结构重写 |
| `needs_review` | 两次重写仍失败或出现越界承诺 | 停止生成，交人工复核 |

最多重写 2 次。材料冲突时列出冲突，不替用户决定哪个事实为真。
