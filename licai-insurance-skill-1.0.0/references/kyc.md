# 客户需求分析与 KYC 画像

## 一、客群分层（先分层，再打法）

| 客群 | 典型特征 | 核心需求 | 沟通基调 |
|------|---------|---------|---------|
| 年轻上班族（22-30） | 收入增长期，储蓄意识萌发但纪律性弱 | 强制储蓄、第一份保障、攒下第一笔钱 | 同频、轻快，讲"习惯养成"，忌说教 |
| 中产家庭（30-45） | 家庭责任高峰，教育金/养老金焦虑 | 子女教育、养老补充、家庭保障兜底 | 专业、共情，讲"确定性"与"家庭责任" |
| 中高净值客户（40+，含企业主/高管） | 资产体量大，关注安全与传承 | 资产隔离、定向传承、利率下行锁利、税务筹划入门 | 平等、顾问式，讲"资产配置逻辑"，忌推销感 |

判断客群先看：年龄、职业、家庭结构、资产负债与现金流，而非收入单指标。

## 二、KYC 五维画像

与客户接触后，按五个维度收集并填写 `assets/kyc-template.md`：

1. **人生阶段**：单身/新婚/育儿期/子女成年/临近退休——决定需求主题词。
2. **财务状况**：收入结构与稳定性、年结余、负债（房贷/经营贷）、已有金融资产——决定预算与缴费方式。
3. **风险偏好**：对波动的容忍度、过往投资行为（存款/基金/股票/房产）——决定主打确定性还是讲配置。
4. **家庭责任**：子女教育规划、父母赡养、婚姻状况（再婚家庭关注传承定向性）——决定保障与传承需求。
5. **已有保障**：已购保单（重疾/医疗/寿险/理财险）、保额缺口、单位福利——决定切入点，避免重复推销。

## 三、需求挖掘提问法（漏斗式四层提问）

原则：多问少讲，让客户说出痛点比说服有效十倍。每层 2-3 个问题，自然穿插不审问。

**第一层 现状切入（建立安全感）**
- "您现在家里钱主要是怎么安排的？存款、基金还是房产多一些？"
- "您和爱人的工作收入都比较稳定吗？"

**第二层 唤醒关注（引导看见缺口）**
- "现在存款利率一年比一年低，您有没有感觉同样的钱，利息少了一大截？"
- "孩子的教育金您是打算到时候再说，还是现在就开始准备？"
- "假设家里突然需要一大笔钱，您手里能马上动用的大概有多少？"

**第三层 量化需求（把痛点变成数字）**
- "孩子 X 年后上大学，四年下来加生活费您估计要准备多少？"
- "您希望退休后每个月有多少被动收入，才觉得比较从容？"

**第四层 确认动机（推向方案）**
- "如果有一个工具，能把这笔钱锁定在一个确定的利率上，写进合同，您愿意先了解吗？"

## 四、需求分析产出标准

完成分析后，向用户输出一份结构化结论，包含：

1. 客群分层与沟通基调
2. 五维画像要点摘要
3. 已识别的 1-3 个核心需求（按优先级排序），每个需求注明"客户原话依据"
4. 切入点建议：先聊哪个需求、用什么问题开场
5. 待确认信息清单（哪些 KYC 信息还缺，建议下一步怎么问）

## 五、常见场景应对

- **客户主动说"想存点钱"**：先问钱的时间属性（多久不动用）和用途（教育/养老/备用金），再匹配产品形态，不要直接报产品。
- **客户是转介绍来的**：开场先借介绍人建立信任（"王姐特意跟我提到您……"），KYC 节奏可比陌生客户快，但仍需完成五维画像。
- **线上微信客户**：前三层提问拆到 2-3 次对话中完成，每次结尾留一个轻问题保持节奏。

## 五、需求点总结标准

需求挖掘完成后，把散落的客户信息浓缩成"需求点清单"，这是衔接产品匹配（`matching.md`）的关键产出。每个需求点按以下格式记录：

| 字段 | 说明 | 示例 |
|------|------|------|
| 需求点 | 一句话概括 | 女儿 6 年后上大学的教育金 |
| 需求分类 | 见下方需求分类矩阵 | 教育金规划 |
| 优先级 | 高/中/低（按客户在意程度与紧迫性，非销售价值） | 高 |
| 客户原话依据 | 原话摘录，无法给出原话的需求点标注"推测，待确认" | "孩子 2032 年高考，到时候一分都不能少" |
| 量化程度 | 已量化 / 待量化（含需追问的数字） | 待量化（追问：四年预算多少） |

输出时需求点不超过 3 个，按优先级排序；没有原话支撑的需求点必须标注推测，禁止把销售意图包装成客户需求。

## 六、需求分类矩阵

| 分类 | 识别信号（原话关键词） | 主打话题 |
|------|---------------------|---------|
| 保障缺口型 | "大病""万一出事""家里靠我" | 收入损失补偿、家庭责任 |
| 教育金规划 | "孩子上学""留学""18 岁要用" | 专款专用、确定时点 |
| 养老补充 | "退休""退休金不够""以后靠谁" | 终身现金流、长寿风险 |
| 强制储蓄 | "存不住钱""月光""想攒钱" | 纪律、习惯养成 |
| 资产传承/隔离 | "留给孩子""定向""婚姻""企业资产" | 指定受益人、确定性传承 |
| 锁利增值 | "利息降了""钱放哪""跑不赢" | 锁定利率、写进合同 |
| 博取更高收益 | "保底太低""想搏一搏" | 保底+浮动机制（合规敏感） |

用途：需求点归类后，直接用于 `matching.md` 的需求→产品形态映射；一个需求点只归一类，主分类决定首选形态。

## 七、客户信息分类归档

每次接触后 24 小时内，把新信息按以下五类归档到客户档案（配合 `assets/kyc-template.md`），形成可长期累积的客户资料库：

1. **基础档案**：称呼与联系方式、生日（含农历/公历标注）、家庭结构与成员称呼（爱人/孩子姓名、年龄、生日——关系经营要用）、职业与爱好、重要纪念日。
2. **财务画像**：收入与结余、负债、已有金融资产与保单（对应五维画像第二、五维）。
3. **保障与需求档案**：历次需求点总结、已推荐方案、客户反馈（认可/犹豫/拒绝及原因）。
4. **偏好与禁忌**：沟通渠道偏好（微信/电话/面访）、活跃时段、忌讳话题（如不愿谈婚姻、忌提某疾病）、对推销的敏感度。
5. **关系网络**：介绍人是谁、可发展为转介绍的潜力、家庭成员中还有谁是需要经营的准客户。

归档纪律：
- 只记事实与原话，不记主观臆断；推测信息标注"待确认"。
- 每次接触后更新"下次跟进动作 + 时间点"（与 ops.md 跟进节奏衔接）。
- 敏感信息（健康、婚姻、收入）仅用于服务客户本人，不外传、不用于无关用途。
